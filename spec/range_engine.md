# Range engine spec

Binding companion to PLAN.md section 5 and spec/data_contract.md. Reference implementation: `core/py/range_engine.py`. Golden vectors: `spec/vectors.json` (generated by `core/py/gen_vectors.py`). All implementations (Python, TS, later Swift) must match the vectors to 1e-9 relative tolerance, using IEEE double precision.

Constants: `Z = 1.645`, `SPAN = 3.29`, `FLOOR_LO = 0.85`, `FLOOR_HI = 1.15`, `LOW_CONF = 0.35`, `SUGAR_VAR = 0.25`, 4 kcal/g sugar, 9 kcal/g oil. `ln` is the natural log.

## 1. Triple to log-normal

A triple `{min, typ, max}` is a 90% interval (5th to 95th percentile), with `min <= typ <= max`.

```
sigma(t) = 0                      if t.min == t.max
         = ln(t.max / t.min) / 3.29   otherwise
median(t) = t.typ
```

- `typ` is always the median. It need not be the geometric mean sqrt(min*max). When it is not, the implied interval is not exactly [min, max], because only the spread (max/min) feeds sigma. This is deliberate: typ is the best point estimate, and min/max only set the width. The final output interval is therefore symmetric in log space around `typ`.
- Validation (any failure is an error: `throw` / `ValueError`): non-finite numbers, `min <= 0` for any log-normal triple, `min > typ` or `typ > max`.
- `min == max` gives sigma 0 (a point value).

## 2. estimateSolid(dish, volumeMl)

Inputs: `dish.kcal_100g` (required triple), `dish.density_g_ml` (required triple when volumeMl is non-null), `dish.default_portion_g` (required triple when volumeMl is null), optional `dish.oil_g_per_100g {min,max}` (0 <= min <= max; absent means 0/0).

**Case A, volume present:**

```
mass_med = V.typ * rho.typ
kcal_med = mass_med * e.typ / 100
sigma_total = sqrt(sigma(V)^2 + sigma(rho)^2 + sigma(e)^2)
```

**Case B, volumeMl is null:** use the default portion as the mass triple. Density is not used.

```
mass_med = P.typ                         (P = default_portion_g)
kcal_med = mass_med * e.typ / 100
sigma_total = sqrt(sigma(P)^2 + sigma(e)^2)
flags += 'portion_default'
```

**Then, both cases:**

```
lo = kcal_med * exp(-1.645 * sigma_total)
hi = kcal_med * exp(+1.645 * sigma_total)
```

**Oil.** `oil` is in grams of oil per 100 g of dish mass. The mass used is **mass_med** (the median mass, for both ends; the oil range already carries its own uncertainty). Oil is added as an interval, not in log space:

```
lo  += oil.min * mass_med * 9 / 100
hi  += oil.max * mass_med * 9 / 100
med += ((oil.min + oil.max) / 2) * mass_med * 9 / 100
```

Note `kcal_100g` is assumed to describe the dish *without* the extra oil; oil is additive.

**Floor** (inputs are partly unverified; the interval is never narrower than +/-15%), applied after oil, using the post-oil med:

```
lo = min(lo, 0.85 * med)
hi = max(hi, 1.15 * med)
```

**Flag** `low_confidence` if `sigma_total > 0.35` (computed before oil/floor). Flag order: `portion_default` first, then `low_confidence`.

Output `{id, lo, med, hi, flags}` (kcal, full precision).

## 3. estimateDrink(drink, sizeMl, sugarLevel, fullSugarGPer700, sugarFraction)

`drink` has `base_kcal_per_700ml` and `toppings_kcal` triples. These may have `min = 0` (min >= 0 is required; they are combined linearly, not in log space). Errors: `sizeMl <= 0`, `sugarLevel` not a key of `sugarFraction`, negative fraction or `fullSugarGPer700`, invalid triples.

```
sugar_g    = fullSugarGPer700 * sugarFraction[level] * sizeMl / 700     (point value)
sugar_kcal = sugar_g * 4
k = sizeMl / 700
```

Shop-to-shop sugar variance is modelled as +/-25% on the sugar term only:

```
lo  = 0.75 * sugar_kcal + base.min * k + top.min
med =        sugar_kcal + base.typ * k + top.typ
hi  = 1.25 * sugar_kcal + base.max * k + top.max
```

Base is scaled linearly by `k`; toppings are **not** scaled by size (a serving of pearls is a fixed scoop). Terms combine by interval (sum of mins, typs, maxes), which is deliberately conservative (it assumes all terms err together). Then apply the same +/-15% floor. Flags: always `['drink_sugar_assumed']`. `low_confidence` is not computed for drinks.

## 4. combineMeal(items)

```
med = sum(item.med)
d_lo = sqrt(sum((item.med - item.lo)^2))
d_hi = sqrt(sum((item.hi - item.med)^2))
lo = med - d_lo ;  hi = med + d_hi
```

Empty list returns 0/0/0. Returns `{lo, med, hi}` only (no flags).

**Independence caveat** (PLAN.md section 5): quadrature assumes item errors are independent. A shared error (for example one bad scale/plane fit) moves all items together, so the meal range may be too narrow. If M5 meal coverage is below 80%, switch the volume term to a linear sum of half-widths. The vectors encode the quadrature version.

## 5. Rounding and display

Compute everything at full precision. Round only for display: `round5(x) = floor(x/5 + 0.5) * 5` (nearest 5, halves up). `formatRange(lo, hi)` returns `"<round5(lo)>–<round5(hi)>"` with an en dash (U+2013), for example `"445–605"`. Never feed rounded values back into the math.

## 6. Vector file format

`spec/vectors.json`: `{version, cases:[{name, fn, input, expected}]}`. `fn` is `estimateSolid` (input `{dish, volumeMl}`), `estimateDrink` (input `{drink, sizeMl, sugarLevel, fullSugarGPer700, sugarFraction}`) or `combineMeal` (input `{items}`). `expected` is `{lo, med, hi, flags}` (combineMeal has `flags: []`) or `{error: true}`. Dish and drink entries are fake and self-contained.
